# PERSONA — старт проекта

Unreal Engine **5.8.3**, Windows x64, C++ и Blueprints. Репозиторий содержит исходники,
импортированного PERSONA, хаб и испытательный стенд. Преследование NPC, присед
и дробовик версии 0.8 описаны в [PERSONA_08.md](PERSONA_08.md).
Исправления сетевой перевозки, оживления и терминала 0.8.1: [MULTIPLAYER_FIXES_VALIDATION.md](MULTIPLAYER_FIXES_VALIDATION.md).
Результаты проверок и записи: [PERSONA_08_VALIDATION.md](PERSONA_08_VALIDATION.md).
Предыдущая проверка физики падения: [PERSONA_07_VALIDATION.md](PERSONA_07_VALIDATION.md).

## Запуск и сборка

Чтобы просто поиграть, дважды щёлкнуть `Start_Game.cmd` в корне проекта.
Если есть актуальная Windows-сборка, откроется она. Если сборки нет или исходники
обновились после её создания, скрипт соберёт C++-модуль и запустит игру через UE
в режиме `-game`, без интерфейса редактора. Первая сборка может занять несколько минут.
Папки `Artifacts`, `Binaries` и `Intermediate` исключены из Git: `git pull`
не переносит готовую игру и не пересобирает модуль.

Для запуска редактора дважды щёлкнуть
`Open_Editor.cmd` в корне репозитория. Он обновляет C++-модуль и открывает проект в установленном UE 5.8.3
с локальным сетевым профилем. После загрузки нажать ▶ Play, затем щёлкнуть внутри игры.
В готовой игре Esc открывает меню паузы; в редакторе Esc также может завершать Play.
Shift+F1 освобождает курсор в редакторе. Папку `persona-trial-and-error 5.8`,
если она создана окном конвертации Unreal, для дальнейшей работы не использовать:
рабочий проект находится в `persona-trial-and-error` без суффикса.

1. Запустить `Scripts/Build.ps1` из PowerShell для сборки редакторского модуля.
2. Запустить `Open_Editor.cmd`. Начальная карта — `L_MainMenu`. Нажать ▶ Play.
3. Для локальных сетевых проверок запустить `Scripts/RunLocal.ps1 -Players 4 -Visible`.
   Для задержки и потерь добавить `-NetworkEmulation`. Завершение тестовых процессов — `Scripts/StopLocal.ps1`.
4. `Scripts/Package.ps1` собирает Windows Development в `Artifacts/Windows`.

Готовая игра запускается без редактора через `Artifacts/Windows/Start_Local.cmd`.
Он открывает главное меню. «Направление в новый сектор» сразу создаёт кооперативный хаб.
«Перевод в действующий сектор» открывает поиск игр в локальной сети; для прямого IP можно
использовать `PersonaJoinIP адрес:7777`. Для Steam использовать `Start_Steam.cmd`
при запущенном клиенте Steam. Переносить на другой ПК всю папку `Artifacts/Windows`.
Для явного запуска имеющейся сборки без проверки её актуальности:
`Start_Game.cmd -Packaged`. Так можно запускать скопированную сборку и на ПК без UE.
После `git pull` заново выполнить `Scripts/Package.ps1`, если нужна обновлённая
самостоятельная игра; прежняя сборка сама не обновляется.

Путь UE определяется через реестр и список установок Epic Games Launcher.
Для нестандартной установки задать переменную окружения `PERSONA_ENGINE_ROOT`
или передать `-PersonaEngineRoot 'путь к UE_5.8'` соответствующему PowerShell-скрипту
(для `.cmd` использовать двойные кавычки). Явно заданный путь имеет приоритет.
Для сборки нужны Visual Studio Build Tools 2022, MSVC 14.44.35229 (или совместимое исправление
ветки 14.44), поддерживаемый Windows SDK (например, 22621), .NET Framework 4.8
SDK/Targeting Pack и Git LFS. В Visual Studio Installer выбрать **Desktop development
with C++**, компоненты MSVC v143 x64/x86 и Windows SDK. UE выбирает установленный
совместимый SDK; проект больше не требует ровно одну версию.
Для запуска готовой сборки Build Tools не нужны.
Для UE 5.8.3 нужен также Visual C++ x64 Redistributable **14.50.35719 или новее**:
запустить `Engine/Extras/Redist/en-us/vc_redist.x64.exe` из установленного UE.
Версия runtime, поставляемая с Build Tools 2022, может быть старее. Скрипт упаковки
включает нужный установщик в `Artifacts/Windows/Engine/Extras/Redist/en-us`.
Windows-пакет содержит шейдеры SM6 и SM5, чтобы работал выбор совместимого режима
на другой видеокарте (в том числе на проверенной Intel UHD).
После клонирования выполнить `git lfs install`, затем `git lfs pull`.
Скрипты проверяют отсутствие пропущенных файлов и текстовых LFS-указателей в Content.

Файлы решений `.sln`/`.slnx` и проекты в `Intermediate` генерируются для каждого ПК
и не хранятся в Git. Для работы в Visual Studio выполнить
`Scripts/GenerateProjectFiles.ps1` после установки инструментов сборки.
Для проверки скриптов запуска без UE и компилятора: `Scripts/TestLaunch.ps1`.

## Управление

| Клавиши | Действие |
|---|---|
| WASD / мышь | Перемещение и обзор |
| Shift / Ctrl / пробел | Бег / приседание / прыжок |
| E | Поднять предмет / использовать объект / открыть или закрыть содержимое хранилища |
| 1 / 2 / 3 | Выбрать слот; пустой слот освобождает руки |
| G | С кастрюлей над свободной конфоркой — поставить по прозрачному предпросмотру; иначе коротко — отпустить весь стак, удерживать и отпустить — бросить с выбранной силой |
| ЛКМ / ПКМ | Выстрел / прицеливание |
| R | Вставить один патрон; удерживать для последовательной зарядки |
| F | Передёрнуть помпу: выбросить содержимое патронника и подать следующий патрон |
| T / B / удержание U | Осмотреть оружие / предохранитель / последовательная разрядка |
| V | Удерживать для голосовой передачи |
| Tab | Закрыть терминал, обыск или контейнер |
| Esc (готовая игра) | Пауза управления, выход в меню с сохранением или завершение игры |

В терминале подвала любой живой участник может принять «Выживание-проворность» или Shooting. Для старта все участники встают на лифт.

В «Выживании-проворности» клавиша **E** поднимает флаг, **G** ставит его. Лес процедурный, а шесть граней вокруг флага смертельны. Возьмите карту из кейса у лифта и нажмите **M**, чтобы увидеть общий исследованный маршрут. За пределами поляны яблоки можно найти у диких яблонь, воду у родников, материалы и редкие патроны в тайниках. Оружие берут с базы. Сложите груз на платформу и нажмите **E** на лифте, чтобы вернуться в хаб. Оставшиеся в лесу получат пустой лифт. Следующая вылазка доступна через 10 минут после завершения предыдущей.

Запас воды виден внизу во всех режимах. Пейте из фляги клавишей **ЛКМ** или включите кран в хабе и используйте его повторно. Погибшего от жажды на базе можно поднять через **E**. В одиночку или после гибели группы нажмите **E**, чтобы очнуться.

В испытании Shooting действуют следующие правила.
Карточка показывает правила, запасы контейнеров для группы и возможную добычу из тел.
Награда — вывезенные предметы: уважения, штрафов за отказ и бонуса патронов больше нет. Затем все живые участники
встают на платформу и используют лифт. Внизу два контейнера с оружием и патронами,
четыре волны NPC и эвакуация. Старый испытательный стенд доступен через панель администратора на клавише под Esc (`/Ё), только у хоста.
Shooting — общее PvE-испытание. Предусмотрен дружественный огонь;
настройка `bFriendlyFire` находится в конфигурации GameMode. Игроки обеих команд слышат соседей.

## Хотбар, дробовик и испытание (0.5)

Внизу экрана три слота, отдельного меню инвентаря нет. Подбор сначала дополняет
существующие стаки, затем занимает свободный слот. Если места не хватает, остаток
остаётся на земле. Дробовик занимает один слот (максимум 1); **12-Gauge Buckshot**
складывается до **20** патронов. Пустые руки полностью скрыты, в том числе при движении.

Два контейнера вместе содержат 48 патронов + 24 за каждого дополнительного
участника и достаточно незаряженных дробовиков для группы.
Обе створки каждого контейнера открывают один общий запас; у двух контейнеров
запасы разные. Молоток, ключ и ящик инструментов на верстаке — неподбираемые декорации.
Кастрюлю можно снять с плиты через E и поставить на любую свободную конфорку через G.
При занятой конфорке она остаётся в руках. Положение поставленной кастрюли сохраняется.
Сохранения прежнего формата обновляются с копией `.pre-interaction-fixes`: содержимое
створок объединяется без пополнения, старые игровые экземпляры декораций удаляются.
Забрать вещи можно через E и небольшое окно у хотбара. В хранилища хаба можно также
складывать предметы; у NPC с вероятностью 25% остаются один или два патрона. Непоместившийся остаток остаётся
в источнике. Дробовик вмещает шесть патронов в трубке и один в патроннике.
Для первого выстрела вставить патрон через R и передёрнуть помпу через F. После каждого
выстрела снова нажимать F. Q не используется. Подробности — в `PERSONA_05.md`.

Скорости: ходьба 600, бег 980, приседание 280 см/с; прицеливание 300 (в приседе 180).
Команда `persona.CameraMotion 0` отключает косметическое движение камеры; значение
по умолчанию — 1. Четыре волны 5/10/20/30 масштабируются по числу участников при
отправлении лифта, одновременно живы не более 30 NPC. Остальные приходят подкреплениями.

Сектор хранит предметы, состояние оружия и незавершённое испытание. «Проследовать
в личный сектор» в главном меню открывает сохранённые секторы. Старые сохранения
обновляются с резервной копией; прежние мировые предметы попадают в миграционное хранилище.

Исходник Blender не перезаписывается. Экспорт — `Scripts/export_items.py`, импорт —
`Scripts/import_items.py`, производные файлы — `SourceArt/Items`. Повторение:

```powershell
Scripts/ImportPhase4.ps1
```

Настройки предметов находятся в `/Game/Persona/Items/DA_Shotgun` и `DA_Ammo12GA`:
название, максимальный стак, модель, положение перед камерой и обе точки хвата.
Для нового типа предмета создать `PersonaItemDefinition` и назначить его `PersonaProp`.
Сервер проверяет дистанцию, луч и владельца; клиент не задаёт количество предметов.

## Steam

По умолчанию активны OnlineSubsystemSteam и SteamSockets, временный App ID **480**.
Хост создаёт сессию, остальные находят совместимую сессию или принимают приглашение через Steam.
Фильтры проекта и версии обязательны, поскольку App ID общий для множества разработчиков.

Проверка настоящего Steam-подключения и VOIP требует двух компьютеров и разных Steam-аккаунтов.
Запустить Steam до Development-сборки. Скрипт упаковки создаёт рядом с exe
`steam_appid.txt` с содержимым `480`; файл исключён из Git. Перед выпуском заменить тестовый ID
собственным и отдельно подготовить Steamworks. Этот проект ничего не публикует.

`-CustomConfig=Local -nosteam` выбирает Null/IP-профиль. Несколько локальных процессов не
являются проверкой голосового чата Steam. Если хост выходит, сессия заканчивается; миграции хоста нет.

## Архитектура

- `PersonaFramework`: GameMode принимает авторитетные решения, GameState реплицирует режим и фазу,
  PlayerState хранит команду, готовность и GAS-атрибуты. Контроллер управляет локальной панелью и голосом.
- `PersonaOnline`: жизненный цикл сессий и приглашения. Локальный и Steam-профили используют разные драйверы.
- `PersonaCharacter` / `PersonaAnimation`: сетевое перемещение, полный персонаж, руки первого лица,
  перенос анимаций и корректирующие формы. Animation Blueprint хранит доступные для настройки клипы.
- `PersonaInteraction`: общий интерфейс, серверная проверка луча взаимодействия, владелец предмета,
  перенос двумя руками, двери и терминалы. Физика свободного предмета авторитетна на сервере.
- `PersonaWeapon` / `PersonaLoot`: помпа, патронник, дробины, реакции попаданий и серверный перенос добычи.
- `PersonaHub`: интерактивные части хаба, подключаемая арена, волны, лифт и эвакуация.
- `PersonaSave`: сектор, игроки, предметы, тела и незавершённое испытание.
- `PersonaAttributes`: GAS, здоровье до MaxHealth, выносливость и сытость 0–100. Голодная шкала означает запас питания:
  100 — сыт. Реалистичный метаболизм будет отдельной системой; на стенде доступны тестовые воздействия.
- `PersonaAI`: серверные зрение и слух, Behavior Tree с патрулированием, исследованием шума и преследованием.
  Шум создают шаги и взаимодействия, а не микрофон. Частота принятия решений — 4 раза в секунду.

На старом техническом стенде хост может выбрать 1, 10 или 30 NPC через панель.
В Shooting числом NPC управляют волны; ручная смена количества во время испытания заблокирована.
Игроки, руки первого лица и NPC используют одинаковый матовый серо-чёрный материал.
Их простой контактный урон служит проверкой здоровья,
а не завершённой боевой системой. Консольные команды: `PersonaNPCs 30`, `PersonaReady`,
`PersonaTrial`, `PersonaHub`, `PersonaMode 1`, `PersonaJoinIP 127.0.0.1:7777`.

## Секторы и сохранения

«Проследовать в личный сектор» показывает отдельные сохранённые секторы. Создание нового
сектора не перезаписывает предыдущий. Сохраняет хост: раз в 30 секунд, при переходе между
картами и при обычном выходе. Сохранения локальные, находятся в `PersonaTrial/Saved/SaveGames/Sectors`
рядом с готовой игрой (для редактора — `Saved/SaveGames/Sectors` проекта).

Сохраняются состояния существующих систем стенда: позиции и показатели игроков, команды,
готовность, поза, предметы и их владельцы, двери, NPC и состояние их поведения на каждой карте.
После отключения участника его тело остаётся в мире и может получить урон. При возвращении
тот же Steam-аккаунт (или локальный профиль) получает это тело без восстановления здоровья.
Удерживаемый им предмет можно забрать. Выход хоста завершает сессию всех участников.
При аварийном завершении доступно последнее успешно записанное состояние; миграции хоста нет.

Запись проверяется перед заменой файла; предыдущая версия хранится в `.bak`. При переносе
локальных сохранений на другой ПК переносить также `Saved/PersonaProfile*.txt`, чтобы сохранить
идентичность локального игрока. Диагностические запуски используют отдельные тестовые сохранения
в `Saved/SaveGames/Validation`, не затрагивая игровые секторы.

`PersonaMenu` содержит главное меню в виде бумажного досье. Настройки, профиль, обучение и
статистика пока показаны бледными недоступными пунктами. `PersonaSave` хранит формат секторов;
новым типам игровых объектов потребуется добавить собственную запись состояния.

## Следующие этапы

Полноценные испытания, оружие и ближний бой, повреждения частей тела, питание,
перенос товарищей, сложное поведение NPC и постоянная прогрессия развиваются поверх этой основы.
Текущая версия не включает выделенные серверы, облачные сохранения и релизную защиту от читов.
